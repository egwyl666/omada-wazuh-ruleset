# Omada → Wazuh: що змінилося

## v5 — SOC з обмеженим доступом, ручне оновлення, опційне автооновлення

**Логіка правил, ID, level і regex не змінювались.**

**Виправлено:**
- `private-ips`: склеєний рядок `172.31.:192.168.:` розділено на два; раніше `192.168.x.x` не вважалась внутрішньою
- старий `update_ti_lists.sh` не знаходив жодного IP Feodo: файл Feodo має переноси CRLF, а пошук ішов по `^IP$`. Правило 100512 фактично не працювало

**Списки:**
- `known-aps` — заглушка замість прикладу; 100505 і далі вимкнене, тепер вмикається видаленням двох рядків з маркером `ENABLE-100505`
- `ti-feodo-c2`, `ti-tor-relays`, `ti-mining-pools` — додано заглушки в `lists/`, щоб правила завантажувались з першого дня
- `mining-pools.txt` перенесено в `docs/` (це не CDB-список і на менеджер не розгортається)

**Threat intel:**
- `update_ti_lists.sh` видалено; основний спосіб — ручне оновлення (README, розділ 7.1–7.3)
- опційне автооновлення в `optional/ti-auto-update/`: завантаження від непривілейованого користувача без доступу до Wazuh, встановлення від root без мережі, сувора перевірка формату, резервні копії, `wazuh-analysisd -t` і відкат; **менеджер не перезапускає** — списки діють після наступного планового рестарту; IP пулів тримаються 30 днів (DNS round-robin); оновлює також `telegram-ips`

**Документація:** README.md / README_UA.md переписано під SOC, який працює в дашборді Wazuh, а решту робить за заявками (шаблони A1–A8); додано розділ про ручне обслуговування всього набору

## v4 — TI, інвентаризація, аномалії

**Threat intel (100512–100514)** — перевірка IP призначення до правил по портах:
- Feodo C2 (abuse.ch) → level 12
- Tor relay-ноди (усі, не лише exit) → level 10
- майнінг-пули (домени з `mining-pools.txt`, резолвляться в IP) → level 10
- старі правила по портах лишились як запасний варіант

**`update_ti_lists.sh`** — оновлює TI-списки:
- качає Feodo і Tor, резолвить пули, збирає CDB-списки
- рестартує менеджер лише якщо щось змінилось (`--restart`)
- якщо завантаження зламалось — лишає старий список
- IP Cloudflare з пулів викидає

**Інвентаризація:**
- 100505 — rogue AP (AP не з `known-aps`). **Вимкнено за замовчуванням** (закоментовано). Щоб увімкнути: заповнити `known-aps` і прибрати коментар
- 100506 — новий невідомий пристрій (MAC не з `known-macs`), один раз на MAC через FTS → level 7
- 100507 — те саме, але MAC рандомізований

**Аномалії:**
- 100620 — 200+ подій/хв на один dst:port (крім web/DNS/NTP) → level 7
- 100621 — 1000+ подій/хв на будь-який порт → level 9

**Off-hours (100630–100633):** remote access і VPN вночі (20:00–07:00) та у вихідні → підвищений level

**Декодер:** додано `<fts>omada.src_mac</fts>`

**Нові файли:** `known-macs`, `known-aps`, `mining-pools.txt`, `update_ti_lists.sh`
